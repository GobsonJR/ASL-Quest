# Admin dataset collection

How administrators collect, review, delete and export **labelled webcam data** (alphabet frames and native-sign clips) in ASL Quest,
what is protected, and what is deliberately *not* part of it.

> **Privacy first.** Every image and clip can show an **identifiable person and their room**. Record only people who have agreed to be
> recorded and to have the files stored, reviewed and exported for building an ASL dataset. Keep exports private, share them only as the
> contributors agreed, and delete a contributor's data when they ask (see [Deleting](#deleting)).

## What is implemented

| Capability | Where |
|---|---|
| Admin-only API, switched off by default | `backend/routers/collect.py` (`ASL_QUEST_DEV_COLLECT=1` **and** an authenticated admin) |
| Consent recorded per session (required) | `POST /collect/sessions` refuses `consent_confirmed != true`; stored in `session.json` with who/when |
| Alphabet frames: capture → quality check → review → confirm label → save | `/collect/analyze`, `/collect/samples` |
| Native-sign clips: record (≤ 10 s) → watch back → confirm sign → save | `/collect/native-clips` (WebM or MP4, ≤ 60 MB) |
| No-hand / partial-hand frames (for false-detection checks) | `/collect/negatives` |
| Review gallery with per-class counts | `GET /collect/sessions/{id}/samples`, `.../native-clips`, `.../image`, `.../video`, `/collect/status` |
| Deletion of any sample/clip/session (audited) | `DELETE /collect/sessions/{id}/samples/{sample}`, `.../native-clips/{clip}`, admin Dataset tab for whole sessions |
| Labelled export (zip + manifest + README) | `GET /collect/export` |
| UI | Admin workspace → **Collect data** tab (`frontend/src/collect/*`) |

## What is **not** implemented (future work, on purpose)

* **No training pipeline here.** Collection and export never train, evaluate, split, promote or replace a model, and never modify the
  existing training dataset (`dataset/asl_alphabet_train/`) or `models/`. How to evaluate on new webcam data is described in
  `WEBCAM_EVAL_PROTOCOL.md`; any training or promotion is a separate, explicitly approved step.
* No automatic blurring/anonymisation of faces, no per-contributor self-service deletion, no encryption at rest (files are plain files
  under `dataset/webcam/`, which is git-ignored).
* Native-sign clips are stored and exported, but nothing in the repository trains a model from them yet.

## Who can use it

* The API requires an **authenticated administrator**. The role is read from the database row of the token's user on every request;
  nothing the browser sends (form fields, local storage, edited requests) can grant it. Anonymous callers get `401`, learners `403`
  — before the "collection is switched off" check, so nobody can probe whether it is on.
* Learners never see the Admin workspace, and the same rule is enforced by the server on every `/admin/*` and `/collect/*` route
  (`tests/test_roles_and_collection_security.py` enumerates the OpenAPI paths and checks each one).
* Administrators are created or promoted by another administrator (Admin → Users → *Add user* / *Make admin*). Ordinary sign-up always
  creates a learner; the only exception is the operator-configured `ASL_QUEST_BOOTSTRAP_ADMIN_EMAIL`, which becomes the **first** admin
  and only while no admin exists.

## Using it

1. Start the backend with `ASL_QUEST_DEV_COLLECT=1` and sign in as an administrator (you land in the Admin workspace).
2. **Admin → Collect data.** Describe the room (lighting, background), name the person (a label such as `person-2`, not an e-mail),
   and tick the consent box. Each room/lighting/background combination is one **session**.
3. Press **Turn on camera** (the browser asks permission; a "Camera on" badge shows while it is live; **Turn off camera** stops it).
4. Choose **Alphabet frames** or **Native-sign clips**, then the letter or sign.
   * Alphabet: **Capture** → look at the exact crop and quality verdict → **Yes, this is C — save** (or Reject). Near-duplicates and
     blurry/too-dark/too-small frames are refused with the reason.
   * Native sign: **Record** → **Stop** → watch it back → **Yes, this is HELLO — save clip** (or Retake / Discard).
5. Review what was saved in the **gallery** (per class), and use **Delete** on anything wrong.
6. **Export** when finished.

Nothing is saved until you confirm the label, and the label is always the one *you* confirm — a model prediction is never consulted.

## Safety checks on the server

* Filenames are generated by the server (`C_<ms>_<hex>.jpg`, `C_<ms>_<hex>.webm`); client names are ignored. Session ids must match
  `s<date>_<time>_<slug>`, sample ids a fixed pattern, and files are resolved from the stored metadata and checked to stay inside their
  folder, so `..` or odd ids cannot reach other files.
* Images: JPEG or PNG only (decoded and checked, not trusted by name), ≤ 8 MB, 64–4096 px per side. Clips: WebM or MP4 judged from
  the file's first bytes, ≤ 60 MB, duration ≤ 120 s. Oversized uploads are cut off while reading. Empty, corrupt or unsupported files get
  `400/413/415/422` and nothing is stored.
* Native-sign labels must be an **active** sign in the catalog; letters must be a single A–Z.
* Sample metadata holds the label, capture time, session id, hand/distance, room conditions and quality metrics. It never holds tokens,
  passwords, e-mail addresses or API keys (tests check the session file and the export for these).
* Saving into a session without a consent record is refused (older sessions made before consent existed stay readable but are not
  extended or exported).
* Every delete, session creation and export writes an **audit log** row (Admin → Audit log).

## Export format

`GET /collect/export` (button **Export** in the workspace; optionally `?session_id=…`) returns `asl_quest_dataset.zip`:

```
README.txt             what the export is, the consent/privacy notice, and "this is not training"
manifest.csv           one row per file
manifest.jsonl         the same rows as JSON lines
images/<LETTER>/<sample_id>.jpg|png      alphabet frames, byte-for-byte as captured
native_clips/<GLOSS>/<clip_id>.webm|mp4  native-sign clips
negatives/<kind>/<sample_id>.jpg|png     frames confirmed to show no usable hand (label starts with "_")
```

Manifest columns: `file, label, label_type (letter | native_sign | negative), session_id, sample_id, captured_at, mode, hand, distance,
contributor, room, lighting, background, consent_confirmed, consent_recorded_at`. Only sessions with a recorded consent are exported;
the response header `X-Export-Skipped-Sessions` and the UI say how many were left out. Keep whole sessions and whole people on one
side of any train/test split.

## Deleting

* A single image/clip: the gallery's **Delete** (confirmed, audited).
* A whole session (e.g. when a contributor withdraws consent): Admin → **Dataset** → *Delete* (type the session id to confirm). This
  removes every file in that session. Files that were already exported are outside the system and must be deleted by whoever holds them.

## Storage layout

```
dataset/webcam/<session_id>/session.json            room, lighting, background, contributor label, consent {confirmed, recorded_at, recorded_by}
dataset/webcam/<session_id>/<LETTER>/<id>.jpg|png   + <id>.json (label, time, hand, distance, quality metrics)
dataset/webcam/<session_id>/negatives/<kind>/…
dataset/webcam/<session_id>/native/<GLOSS>/<clip_id>.webm|mp4  + <clip_id>.json
```

`dataset/` is git-ignored: collected frames and clips are never committed.
